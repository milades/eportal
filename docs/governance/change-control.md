# کنترل تغییر

## تغییر عادی داخل فاز

تغییری عادی است که هم‌زمان:

- مستقیماً به یک Work Item مصوب فاز فعال نگاشت شود؛
- معماری، امنیت، محدوده و معیار پذیرش را تغییر ندهد؛
- به محیط یا سامانه خارج از Repository اثر نگذارد؛
- قابل آزمون و برگشت باشد.

## تغییر نیازمند Change Request

هر مورد زیر قبل از اجرا به Change Request نیاز دارد:

- تغییر Scope، معماری، فناوری یا قرارداد امنیتی؛
- پذیرش NTLM یا کاهش رفتار fail-closed؛
- افزودن مرورگر، اینترنت، موبایل، Role/Group/OU، MFA، IdP یا API؛
- ورود HA، Backup، Monitoring یا CI/CD اختصاصی به محدوده؛
- تغییر معیار ظرفیت، UAT، نگهداری Audit یا سیاست نشست؛
- تغییر واقعی Production؛
- عملیات مخرب یا برگشت‌ناپذیر روی Git، SQL یا زیرساخت.

## محتوای Change Request

1. شناسه و عنوان؛
2. مسئله و دلیل؛
3. محدوده فعلی و تغییر پیشنهادی؛
4. اثر امنیتی، عملیاتی، زمانی و هزینه‌ای؛
5. گزینه‌ها و تصمیم پیشنهادی؛
6. آزمون و معیار پذیرش؛
7. Rollback؛
8. ADR مرتبط، در صورت معماری‌بودن؛
9. تأیید مالک و مسئولان زیرساخت مربوط.
